# SASN 方法细则与反例库

## 四机制依赖关系
SASN 的四机制有严格先后；跳过前置会级联失败：

- **对得上（Section-Aligned Skeleton）→ 留得住（Paper Card Fields）**：只有先按论文本身章节建骨架，字段才有落节位置与承接关系。
- **留得住 → 找得回（Source Anchors）**：字段与笔记成形后，逐条回链才知道"锚定哪条结论"。
- **找得回 → 用得上（Reusable Knowledge）**：有可靠锚点的知识点才能被后续核验、比较与加工。

## 机制一：对得上 —— 章节对齐骨架
- 骨架来源：论文自身的标题、摘要、章节编号与层级、论证顺序，**不是通用摘要模板**。
- 每节记录：`section_id`、`level`、`number`、`title`、`page`、`transition_from/to`（承接关系）。
- 章节切分要能被独立复核：给出切分依据（标题样式/编号/页码）。
- 存疑标 `section_uncertain`，不强行归一到模板。

## 机制二：留得住 —— 论文卡片字段化
七类硬字段，缺一不可（原文未报告则写"原文未报告"并进 uncertainties）：
1. research_question 研究问题
2. data 数据
3. method 方法
4. method_conditions 方法成立的条件
5. main_findings 主要发现
6. limitations 局限
7. conclusion_preconditions **让结论成立的前提条件**
- 数值、变量、方法条件与原文逐字一致；前提与局限不得因"摘要没写"而省略——原文确有则记，原文未写明则如实标注。

## 机制三：找得回 —— 来源锚点
- `source_anchor` 五要素：章节 + 段落 + 页码 + 图表/公式编号 + 原文依据。
- `source_anchor_map` 的 `claim` 必须来自笔记中的实际论断或数值；一结论一锚点。
- 锚点粒度与可核验性匹配：关键结论精确到段落或图表，不笼统写"第 X 节"。
- 无锚点的结论不得保留在笔记中。

## 机制四：用得上 —— 可检索可比较可加工
- 知识点拆条：`kp_id`、`term`、`type`（concept/variable/method/finding）、`definition`、`aliases`、`source_anchor`。
- 术语/缩写/同义登记到 `term_registry`，归一到 `normalized`，避免重复条目与互相矛盾。
- 字段统一使同领域多篇论文可并排比较；输出结构化数据便于检索与继续写作。
- 矛盾条目进 `human_review_items`，不擅自择一。

## 抽取与复核分离
抽取阶段禁止自我复核；抽取完成后以"复核者"身份独立执行 checklist，发现错误回退对应步骤并写 `change_log`。合并两遍会漏掉自己引入的字段遗漏与锚点错位。

## 反例库
| 反例 | 为什么错 | 改法 |
|---|---|---|
| 用通用模板"背景/方法/结果/结论"套所有论文 | 脱离论文自身论证顺序，对不上 | 先抽论文本身章节建骨架 |
| 只记结论不记前提与局限 | 结论被当成无条件成立，不可复用 | 硬字段强制，原文无则标"原文未报告" |
| 出处只写"第 3 节" | 粒度太粗，无法回查具体论断 | 锚点精确到段落/图表/页码+basis |
| 把方法条件写进"方法"混为一谈 | 条件丢失，结论适用范围不清 | method_conditions 单列字段 |
| 同一概念出现 3 个条目（缩写/同义/全称） | 重复矛盾，不可检索 | term_registry 归并，normalized 归一 |
| 数值与原文不符（凭印象写） | 正确性失败 | 逐字核对，存疑进 uncertainties |
| 替论文补外部事实或评价科学价值 | 超出材料，违反边界 | 只记论文已写内容，评价进 human_review |
| 无对照记录却自称"结构性提升" | 自述不能替代证据 | 用 self_check 与字段完整性证明，不编 benchmark |
